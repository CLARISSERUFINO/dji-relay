# Phase F4 results: telemetry, events, clock beacons, database, analysis

F4 is done in three steps, each validated before the next:

- **F4a**: messages from the phone (UDP 5601) and the `drone` database.
- **F4b**: `vision_logger`, Grafana, scripts.
- **F4c**: analysis (E7, E10) and the decision on spec 10.2 step 3.

Bench tests are done with the **propellers removed**. DJI Fly must be closed.

## F4a: messages and the `drone` database

### Setup

| Item | Value |
|---|---|
| App version / branch | `0.4.0-f4` / `f4-telemetry` |
| `drone_logger` | `ssl-aggregator`, branch `feature/dji`, built in `ssl-aggregator/build/` |
| Database | `robot_data`, schema `drone` created with `sql/04_drone.sql` (backup taken first with `scripts/db_dump.sh`) |
| Expected profile | `DRONE_EXPECT_WIDTH=1440`, `HEIGHT=1080`, `FPS=30`, `MIME=H264` |
| Protocol | `docs/protocol.md` (5600 video, 5601 messages) |

### Telemetry keys

All 26 keys of spec 7.7 exist in `dji-sdk-v5-aircraft-provided` 5.20.1 (checked with
`javap`). They are declared in `DJIFlightControllerKey` (`KeyFlightMode` in
`FlightControllerKey`), `DJIGimbalKey`, `DJICameraKey` (`KeyCameraStorageInfos` in
`CameraKey`), `DJIBatteryKey` and `DJIAirlinkKey`, and reached through the public
subclasses. Values are serialized with `DJIValue.toJson()`, enum names, or as plain
numbers, booleans and strings; `CameraStorageInfos` from its getters.

On the bench, 24 of the 26 keys report values. The other two have no value yet:

| Key | `getValue` result | Reason |
|---|---|---|
| `KeyAircraftLocation3D` | `REQUEST_TIMEOUT` | No GPS position (`KeyGPSSignalLevel` = `LEVEL_0`) |
| `KeyNewlyGeneratedMediaFile` | `REQUEST_TIMEOUT` | No media file recorded yet (recording comes in F5) |

The two gimbal keys fail `getValue` right at aircraft connection
(`REQUEST_HANDLER_NOT_FOUND`) but report normally a moment later.

### Bench run

One `drone_logger` run with several live streaming sessions (the app was restarted
while the telemetry snapshot was being fixed, see Issues):

| Table | Rows | Check |
|---|---|---|
| `drone.live_frame` | 7568 | all complete; 0 lost packets; 7300 (96.5 %) with an injection time |
| `drone.phone_frame` | 7617 | one per access unit sent |
| `drone.clock_beacon` | 2550 | 10.0 beacons/s, 0 sequence gaps |
| `drone.telemetry` | 1034 | 24 keys |
| `drone.event` | 27 | `session_start`, `key_rates` |
| `drone.config_check` | 4 | `w`, `h`, `fps`, `mime`: all OK, 0 mismatches |

`drone_logger` health line during the run: 30 frames/s, 0 lost packets, 0 incomplete,
about 43 messages/s, 10 beacons/s, 0 beacon gaps, 0 invalid messages, database backlog 0.
The clock lower envelope moved by +0.59 ms over the run (a first look at the drift;
E7 in F4c measures it properly).

`key_rates` on the bench: most keys at 0 Hz, attitude about 0.3 Hz, takeoff altitude
about 1.9 Hz. With the drone on the ground, most values do not change. The real rates
(V7) need a flight.

The frames without an injection time are the first ~0.5 s of each stream (known from
F3) and frames still waiting when a stream stopped.

### Issues found

1. **Telemetry values missing until they change.** Keys subscribed at registration,
   before the drone is connected, only reported later changes, and messages built while
   live streaming was off were lost. Fixed: the keys are subscribed again when the
   aircraft connects, and a snapshot (`KeyManager.getValue` for every key, sent with
   `"snapshot": true`) is taken on aircraft connection, live streaming start and phone
   recording start.
2. **`getValue` overload ambiguity in Kotlin.** With a key typed `DJIKey<Any>`,
   `getValue(key, R defaultValue)` also matches a callback object. The read is done in a
   generic helper, where only the callback overload applies.

### Open points

1. **Database outages longer than about 1.5 s lose rows.** `common::BatchWriter` (existing
   `ssl-aggregator` code) drops a batch after 3 failed attempts 0.5 s apart. NFR4 asks
   `drone_logger` to tolerate a temporarily unavailable database. To be addressed with E6
   (F6).
2. **V7 (real key update rates)** needs a flight.
